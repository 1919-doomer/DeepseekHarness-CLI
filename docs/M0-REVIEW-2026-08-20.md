# M0 final review — 2026-08-20

## Purpose

Record the final development-readiness review immediately before M1 implementation.

## Upstream baseline reviewed

Official repository: `deepseek-ai/deepseek-harness`

Observed baseline on 2026-08-20:

- root version: `0.1.0-rc.8`;
- package manager: pnpm `11.7.0`;
- Node engine: `^22.19.0 || >=24.0.0`;
- TypeScript/ESM project;
- official TypeScript SDK client drives a Harness runtime subprocess over stdio JSON-RPC;
- runtime protocol remains newline-delimited JSON-RPC 2.0;
- client requests: `initialize`, `session/prompt`, `shutdown`;
- server notifications: `session.event`, `session.status`, `subagent.started`, `subagent.finished`;
- `session/prompt` returns a durable enqueue receipt/message id, not an exact assistant result;
- no negotiated protocol version beyond current server metadata contract;
- no per-prompt cancellation or per-session close method.

## Architecture review result

**PASS.** Existing `dshc` architecture remains compatible with the reviewed public boundary:

- external two-process host remains appropriate;
- official SDK/runtime is preferred over private Harness imports;
- event-native local projection remains necessary;
- process-level shutdown remains the only coarse interruption fallback when no cancel method exists;
- no full-screen TUI is required to prove M1.

## Product review result

**PASS with a strategic guardrail.** The project has a defensible reason to exist only as a DSH-native terminal console, not as a generic coding-agent clone. `docs/DIFFERENTIATION.md` and issue #15 record this requirement.

## Security review result

**READY FOR IMPLEMENTATION, NOT READY FOR RELEASE.** The threat model identifies terminal escape injection, credential leakage, protocol confusion and process cleanup as implementation/release gates. These must be proven by tests in later milestones.

## Testing review result

**PASS.** Core correctness can be tested without paid model credentials using pure unit tests, protocol fixtures and a fake runtime process. Required CI must remain credential-free.
