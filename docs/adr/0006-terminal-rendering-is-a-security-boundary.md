# ADR 0006 — Terminal rendering is a security boundary

Status: accepted
Date: 2026-08-20

## Context

`dshc` renders model output, tool output, filenames, repository content and runtime diagnostics. Those strings may contain ANSI/OSC/control sequences capable of changing terminal state or misleading the user. The upstream Harness is not responsible for sanitizing content for this independent frontend.

## Decision

All externally derived display content is untrusted terminal input. Active terminal control sequences must be neutralized at the `dshc` rendering boundary before display. Styling/control sequences may only be generated by trusted renderer code.

Sanitization is required even in the plain M1 renderer and is a blocker for public alpha.

## Alternatives considered

- Trust upstream text: rejected because upstream has a different presentation boundary and cannot guarantee this frontend's terminal safety.
- Sanitize only model text: rejected because tool output, filenames, repository content and diagnostics can carry the same attack surface.
- Add sanitization only in the final TUI: rejected because the plain CLI renderer is also a terminal surface.

## Consequences

- rendering functions need a clear trusted/untrusted text boundary;
- adversarial ANSI/OSC/control fixtures are required;
- raw untrusted output cannot be passed directly to stdout for interactive rendering;
- plain/non-TTY behavior must remain readable after sanitization.
