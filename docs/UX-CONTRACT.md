# Terminal UX contract

This document defines behavior, not visual styling. M1 proves these semantics with a plain renderer; M3 may replace presentation without changing the contract.

## Transcript model

The transcript is a projection of normalized Harness events. It has two classes of state:

- durable: user messages, committed assistant messages, tool calls/results, errors, subagent lifecycle summaries;
- ephemeral: streaming chunks, spinner/activity text, elapsed time, active tool/subagent count.

The UI may visually group events but must preserve meaningful order and must never fabricate unsupported causal relationships.

## Runtime states

Minimum local states:

`starting -> initializing -> idle -> running -> idle -> shutting-down -> closed`

Failure may occur from any process-owning state and must carry an actionable reason. The UI must distinguish runtime exit, transport failure, protocol error, configuration error and model/tool outcome when the wire makes that distinction observable.

## Prompt behavior

- A submitted prompt is queued through the official SDK/runtime contract.
- The returned `messageId` is an enqueue receipt, not an assistant result id.
- The input surface should remain conceptually separate from runtime activity so M2 can support queued/steering behavior if upstream semantics permit it.
- Do not label the next assistant message as cryptographically/causally 'the response to prompt X' unless upstream provides that guarantee.

## Streaming behavior

Streaming chunks may update ephemeral text in place. When a committed assistant message arrives, the renderer must converge to the committed form without printing the same text twice.

## Tool rendering

Every state-changing tool execution exposed by the event stream must remain inspectable. The UI should distinguish at least:

- read-only activity;
- file/content mutation;
- subprocess/shell execution;
- result/error state.

Large output may be folded but must not be silently discarded when the user needs to inspect it.

## Subagents

Root-session activity and descendant activity must be distinguishable. Subagent started/finished notifications should form a readable lineage/activity view without pretending that `dshc` owns subagent scheduling.

## Slash commands

Initial local command contract for M2:

- `/help` — list local commands;
- `/status` — show runtime/provider/model/workspace/session state;
- `/session` — show current session information;
- `/new` — create/select a fresh session according to supported SDK semantics;
- `/clear` — clear local terminal projection only; never delete Harness history silently;
- `/exit` — graceful runtime shutdown.

Candidate later commands (`/agents`, `/model`, `/resume`, `/compact`) require an explicit supported upstream capability before implementation.

## Ctrl+C and interruption

Current upstream protocol does not expose per-prompt cancellation.

Therefore:

- while idle, Ctrl+C may clear current input;
- while running, the product must not display 'cancelled' unless a real terminal condition is known;
- destructive process-level interruption must be explicit because it abandons the owned runtime, not just one prompt;
- repeated Ctrl+C may escalate to process termination according to the lifecycle policy;
- future upstream cancellation should replace the fallback behind the adapter rather than change user-facing command structure unnecessarily.

## EOF and exit

EOF/exit initiates graceful shutdown. Runtime stdout remains protocol-only; human diagnostics belong on the terminal host side and/or stderr. Exit status is non-zero for startup/transport/protocol failures.

## Terminal safety

All model content, tool output, repository text, filenames and diagnostics are untrusted display input. Active terminal escape/control sequences must be neutralized before rendering. Styling sequences are generated by `dshc` itself, never passed through from untrusted content.

## Accessibility and readability

- correctness cannot depend on color;
- status must remain understandable in narrow terminals;
- important errors must contain text labels, not icon-only meaning;
- reduced-color/non-TTY output should remain usable;
- full-screen mode must not be required for scripted/non-interactive operation.

## Visual non-goals before M3

Do not spend M1/M2 effort cloning another product's spacing, spinner glyphs, colors or panels. The product identity comes from Harness-native semantics and terminal clarity, not visual imitation.
